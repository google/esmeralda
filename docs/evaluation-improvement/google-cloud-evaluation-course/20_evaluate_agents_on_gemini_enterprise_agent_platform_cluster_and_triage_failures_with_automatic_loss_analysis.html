Cluster and triage failures with Automatic Loss Analysis

Source: https://storage.googleapis.com/cloud-training/cls-html5-courses/P-VEEPTD-A/content/index.html#/lessons/AMmxG3qkVZOVtEbHdb3vh4r7_kM2DGT-

Automatic Loss Analysis analyzes the pass or fail signals from rubric-based metrics, classifies failures into predefined loss patterns, and groups them into semantic clusters. This tells you not just that the agent failed, but shows how many types of issues there are and which ones are more frequent.

A cluster is the unit you act on: each one is a recurring way the agent fails, so you fix a root cause once instead of triaging individual issues one at a time.

You do not run this as a separate step in the console. Automatic Loss Analysis runs as part of the evaluation, and you read its output in the Failure Clusters section of a completed run's report. Each cluster carries a category, a loss pattern, example scenarios, and a rationale for why the grouped cases failed. Clusters appear only when the run detects a recurring pattern, so a clean run shows none. From the SDK, you can also generate them on demand with client.evals.generate_loss_clusters, where they are called loss clusters.

Start from a cluster's category. It already classifies the failure, for example as an Instruction Following or Tool Calling issue, before you open a single case.

A cluster tells you what kind of failure happened; you still have to find where it happened.

  1. Move from the summary metrics, through the per-case results, into the trace.

  2. Start at the summary to find the lowest-scoring metric.

  3. Drill into the per-case results to open a failing eval case.

  4. Read its rubric Pass or Fail verdicts and the natural-language rationales beside the trace.

Each failing case keeps its category, so the classification follows you from the cluster down to the individual case. The trace then shows the full conversation and the exact sequence of model inputs, tool calls, and responses, which is where you backtrack to the root turn.

Tip: Start from the lowest-scoring summary metric, not the largest cluster. The weakest metric usually points at the cluster worth fixing first.
