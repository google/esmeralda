Operational telemetry metrics capture the quantitative runtime behavior of a generative or agentic system. They measure system performance and execution characteristics rather than the quality or correctness of the output.

These metrics are cheap to measure and available instantly, serving as a first line of defense in automated testing and monitoring. They also capture critical resource constraints that you must balance against output quality in a comprehensive evaluation plan.

Deterministic correctness checks evaluate outputs against strict logical, mathematical, or programmatic rules. These checks yield binary or quantifiable results without subjective ambiguity.

Unlike similarity metrics, these checks do not compare fuzzy semantic overlap. Instead, they verify the output against a single correct 'oracle' answer, or validate unambiguous functional compliance. Examples include exact match comparisons, mathematical range checks, and JSON schema validations.

Deterministic correctness checks require a single correct answer, a known structure, or a testable requirement. They are ideal for classification, structured data extraction, SQL generation, sandboxed code execution, and mathematical operations.

Conversely, they are impossible for open-ended tasks. If an agent writes a shipping delay email, there is no single target text. Thousands of valid variations exist, rendering exact match metrics useless.

When a task is open-ended, exact match checks fail because there is no single correct response.

Relying on these overlap-based metrics for open-ended outputs falls into the single ground truth trap. This trap occurs when you assume that because a human wrote one reference text, any deviation from that specific text is incorrect. 

For example, consider a customer support agent generating a summary of a chat history:

  • Reference: "Customer requested a refund for a damaged shirt. Refund approved."

  • Output A: "A shirt was damaged, so the user asked for a refund, which we granted."

  • Output B: "Refund approved shirt damaged customer shirt refund shirt."

Output A is semantically perfect and helpful. However, because it uses synonyms (like 'user' and 'granted' instead of 'customer' and 'approved'), its BLEU and ROUGE scores are very low.

Output B is a nonsensical string of keywords. Yet, because it shares exact vocabulary words with the reference, its overlap scores will be higher than Output A's. Even METEOR is misled by Output B, grading it higher than Output A.

Although calculating BLEU or ROUGE is programmatic and deterministic, these metrics rely heavily on human judgment in two key ways:

  1. 1.

    Reference creation: The reference texts must be authored by humans. The metric is only as good as the quality and diversity of these references.

  2. 2.

    Calibration: You must calibrate the metric first. This requires human experts rating a sample of outputs, and verifying that the calculated similarity scores agree with human judgment.

The centralized gateway architecture

Prior to generative AI, similarity metrics had value. Today they are mostly outdated. Human annotation effort is far better spent on calibrating automated rubrics (discussed later in this course) than on calibrating similarity scores.

Every evaluation methodology has trade-offs. You must understand the strengths and weaknesses of deterministic metrics to design an effective evaluation plan. 

Strengths 

  • Low cost: Programmatic checks run on local CPU compute for free, requiring no model API calls. Operational telemetry is already available.

  • High speed: These metrics execute in milliseconds, allowing rapid evaluations ideal for automated CI/CD pipelines.

  • Perfect repeatability: As mathematical formulas, they are 100% repeatable.

Weaknesses

  • Superficiality: They cannot evaluate high-level quality attributes like tone, helpfulness, reasoning, safety, or factuality. Telemetry indicates system efficiency, not output quality.

  • Rigidity: String checks are fragile. Minor differences in formatting or spelling can trigger false failures on semantically correct outputs.
