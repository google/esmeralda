In this lesson, you'll learn how to create synthetic data to evaluate generative and agentic systems.

While online evaluation data is essential, it is not always available or sufficient. Synthetic evaluation data can fill this gap. You'll explore the advantages and risks of synthetic data, and learn how to generate synthetic evaluation data using both single prompts and simulated users.

By the end of this lesson, you'll be able to:

  1. Explain the benefits and risks of using synthetic data for evaluation.

  2. Apply best practices to generate diverse single-turn simulated evaluation data.

  3. Explain how to configure multi-turn user simulations to generate synthetic evaluation data.

Synthetic data can fill this gap.

In the context of generative AI, the best way to create synthetic data is through simulation. Using generative AI, you simulate things a user might input into your system, or even full user interactions. Your system then responds to these simulated inputs as if they were real users, giving you synthetic evaluation data.

The primary use of synthetic evaluation data is during hill climbing to:

  • Identify and fix specific deficiencies.

  • Ensure the system can handle critical edge cases.

  • Maintain output quality regression test coverage where real evaluation data is scarce.

The following sections cover two kinds of data simulation:

  1. Single turn: Prompting a model to generate prompts that will then be fed into your system one at a time.

  2. User simulation: Directing an AI to impersonate a user.

The centralized gateway architecture

To simulate single-turn interactions, you use a foundation model to generate large numbers of prompts that will then be fed into your system one at a time. The simulation ends once your system generates a final response; there are no additional turns in the interaction.

For example, you may want to test an e-commerce chatbot's ability to answer questions about a return policy. You start by gathering a list of 1000 of your products. You then might provide a template like "Can I return [product] because [reason]?" and generate 5 prompts for each product asking the model to come up with [reason], potentially providing some instructions on what a good [reason] looks like.

The centralized gateway architecture

Alternatively, you may provide more open-ended instructions to the LLM asking it to generate a product return request, letting the model be more creative.

To prevent the generator model from creating homogenous (repetitive) prompts, you can apply two advanced techniques:

  1. Embedding-based topic clustering: Generate a large pool of prompts, calculate their embeddings, and cluster them. You can then identify and prune over-represented clusters to ensure broad coverage.

  2. Persona-based generation: Seed the generator prompts with specific target user personas. For example, instruct the model to generate inputs from a "first-time buyer," an "impatient customer," or a "disgruntled returner." You can use the model to help you create a long and rich list of different personas for your simulation task.

The centralized gateway architecture

Evaluating conversational, multi-turn agents requires more than single-turn prompts. The system's response depends on the context of the entire conversation. To evaluate these systems, you must use user simulation.

User simulation is an evaluation technique where specialized user agents act as virtual users to interact with and test the target system.

Simulating users requires careful configuration and monitoring. Because simulated user agents generate free-form responses, the risk of generating inappropriate outputs is higher than in single-turn generation.

To test conversational agents, you configure simulated user agents with specific goals and rules:

  1. Define a persona: Give the simulated agent a persona, such as an increasingly frustrated customer.

  2. Set a conversational goal: Instruct the simulated agent to achieve a goal, like returning an item.

  3. Introduce conversational shifts: Tell the agent to change its mind mid-conversation (for example, switching from returning item A17 to returning item B12) to test how well the target system maintains context.
