In this lesson, you'll learn how the development lifecycle of generative and agentic systems is driven by evaluation.

Building generative and agentic systems requires moving away from traditional deterministic pass-fail testing because model outputs are probabilistic. Instead, you must use an iterative, evaluation-driven lifecycle to guide development. You'll trace this process through the six stages of development, from setting goals to production monitoring, using a walkthrough of an e-commerce chatbot.

Finally, you'll examine how evaluation shifts from early qualitative vibe checks to system-level offline simulations and online telemetry, and how real-world failure logs feed back into offline golden datasets for continuous optimization.

By the end of this lesson, you'll be able to:

  1. 1.

    Differentiate between deterministic software testing and probabilistic evaluation in generative and agentic systems.

  2. 2.

    Explain the six stages of the generative and agentic system development lifecycle using an e-commerce support chatbot walkthrough.

  3. 3.

    Analyze how evaluation objectives, methodologies, and datasets shift across the development lifecycle.

  4. 4.

    Describe how production telemetry feeds back into offline evaluation datasets to form a continuous improvement loop.

The centralized gateway architecture

Traditional software development is deterministic. You write code, compile it, and run unit tests with binary assertions. The code either works or it does not. Testing is a validation gate that you run after the code is written.

Building generative and agentic systems is different because models are probabilistic. The same prompt can produce different outputs on consecutive runs. Because of this uncertainty, you cannot use traditional binary tests. If you do, your tests will fail randomly or miss critical regressions.

Instead, the development lifecycle for generative and agentic systems is an iterative, feedback-driven loop powered by quantitative measurement. Evaluation is not just a post-development check. It is the engine that drives every phase of design and optimization.

Your evaluation strategy must evolve as your system transitions from a rough prototype to a live production application. What you measure, how you measure it, and who performs the evaluation will shift dramatically across the lifecycle.

Understanding these shifts prevents two common mistakes, namely:

  1. 1.

    Over-engineering evaluations too early
    (which slows down initial prototyping)

  2. 2.

    Relying on informal "vibe checks" too late
    (which leads to catastrophic production failures)
