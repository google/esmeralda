In this lesson, you'll learn how to scale your evaluation pipelines using autoraters—automated systems that use foundation models to rate outputs against structured rubrics.

While human annotators remain the gold standard, evaluation at scale requires automation. Autoraters execute tirelessly at near-zero marginal cost, enabling rapid iteration and continuous monitoring. However, you cannot deploy them out-of-the-box. You'll learn when autoraters are appropriate, review potential issues with autoraters, and understand how to use autoraters effectively.

The centralized gateway architecture

Human annotation is the gold standard for generative and agentic system evaluation, but it is slow, expensive, and impractical to scale.

The centralized gateway architecture

Autoraters solve this scaling problem by automating the evaluation process. An autorater is an evaluation system that uses a generative model to rate other outputs. Terms like "LLM-as-a-judge" or "judge model" are also used for this concept. This course uses the more general term "autorater".

Autoraters evaluate outputs by following a structured rubric, acting as automated evaluators.

However, autoraters are not a risk-free evaluation shortcut. To use them successfully, you must establish two key prerequisites:

  1. Clear, objective rubrics: You must provide the autorater with clear, objective instructions that define how to rate each quality dimension.

  2. Human calibration: You must calibrate your autorater against a human judgement. This ensures the autorater matches human ratings.

Note you should always run autoraters with the default generation settings for a model, especially temperature.

Counterintuitively, research has shown setting temperature = 0 makes autoraters less likely to match human judgment.

Conversely, avoid the use of autoraters for simple, deterministic tasks. This is an anti-pattern.
For example:

  • Checking if a response is valid JSON.

  • Verifying mathematical equations or interest rate calculations.

  • Extracting simple dates, names, or values that fit regex patterns.

Always exhaust all meaningful deterministic checks first. If a programmatic check can verify output correctness, do not pay the cost or accept the shortcomings of an autorater.

Measuring Rubric Consistency (Agreementk)

When following human calibration best practices is impractical, you can run a self-consistency test on the autorater itself.

  • Run the autorater 5 to 10 times on the same (representative) dataset using the same rubric.

  • If the autorater's ratings are consistent, it might be safe to use the autorater with the rubric (though you should still perform some kind of human calibration, even if only vibe calibration).

  • If the ratings vary, it is not safe to use the autorater with the rubric. The autorater ratings will be inconsistent, and thus useless for comparative purposes. You can't even meaningfully do vibe calibration in this situation.

  • You might be able to achieve autorater rating consistency by reviewing the cases where the autorater disagreed with itself and patching your rubric accordingly.

Note that "consistency" for a rubric does not necessarily mean ratings match exactly all of the time; Module 3 discussed the concept of creating rubrics in more detail.

As mentioned previously, autoraters do not work well with temperature=0. For this self-consistency technique specifically, setting temperature=0 forces more predictable output, rendering the technique essentially useless.
