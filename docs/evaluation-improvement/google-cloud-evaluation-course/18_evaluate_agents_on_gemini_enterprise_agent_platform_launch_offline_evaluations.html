Offline evaluation scores data you already have. This lesson covers the two ways to run it: a bulk run that scores many traces or sessions, and an ad-hoc run that scores a single one.

A bulk evaluation scores many captured traces or sessions at once, so you measure the agent's quality across a version or a time window rather than one response. It is a bulk run because you select many items at the wizard's filter step.

  1. You start it with the New Experiment wizard on the Evaluation page. The wizard offers three data sources: Traces, Sessions, and Simulate sessions.

  2. For data you already have, pick Traces or Sessions: a trace is one turn, a session is a whole conversation.

  3. Filter to what you want graded, for example by Version or a time window, then select the IDs.

  4. Give a Cloud Storage URI in the Output private data path field for the results.

  5. The four core metrics are added by default, and you adjust them before you run.

Tip: Choose the Sessions tab when the behavior you care about plays out across turns. The Traces tab grades a single turn.

Some failures show up only across a whole conversation: a wrong assumption compounds over several turns while each response looks reasonable on its own. To grade one such conversation on demand, use the ad-hoc Evaluate action rather than a full bulk run.

  1. You reach it from the agent's Traces tab.

  2. Open Session view, which lists every captured conversation, select one, and on its detail panel open the Evaluation sub-tab, then click Evaluate.

  3. The Agent Multi-turn Task Success metric is what catches conversation-level failures here: it scores whether the conversation reached its goal, so a problem that only emerges across turns shows up as a low session score.
