The centralized gateway architecture

The reference metrics check the exact tool calls and wording. LLM-judge metrics check whether the answer means the right thing. A judge model scores semantic quality, rubric adherence, hallucination, and safety, and a separate family grades whole multi-turn conversations.

The centralized gateway architecture

Build-time evaluation and the managed platform work together as one Quality Flywheel. Once the agent passes locally, you deploy it to Agent Runtime and evaluate it through the managed client.evals API from Modules 5 and 7. That covers scenario generation, the User Simulator, rubric metrics, online monitors, and issue clustering.

This bridge closes the loop the whole course has been building. You got oriented (Module 1), instrumented the agent (Module 2), generated eval cases (Module 3), defined metrics (Module 4), ran offline evaluations (Module 5), monitored production and alerted on drift (Module 6), and diagnosed, optimized, and verified fixes (Module 7). This module added the build-time half. It catches regressions in ADK before you deploy. Together they form one continuous Quality Flywheel, from a developer’s machine to live production. You now have the map and the tools to run that loop on your own agent.
