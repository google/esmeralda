The same eval data runs from three entry points, each suited to a different situation.

  1. The adk web UI is for interactive debugging.

  2. The adk eval CLI is for scripted and CI runs.

  3. The pytest entry point folds evaluation into your test suite.

Tip: Both reference metrics ship with defaults, so a run with no config still grades them. tool_trajectory_avg_score defaults to an EXACT match at threshold 1.0, and response_match_score defaults to 0.8. Every other metric’s threshold is something you set explicitly. Don’t assume one exists.

The centralized gateway architecture

A test_config.json file maps each metric to a pass threshold, so you decide how strict the run is. The simple form takes a number. The extended form lets you relax the tool-trajectory check from an exact match to an ordered or any-order match.

Valid match_type values are EXACT, IN_ORDER, and ANY_ORDER. Because model output varies between runs, AgentEvaluator.evaluate() also accepts num_runs to repeat each case and average the result. That keeps a nondeterministic agent from failing on a single unlucky run.
