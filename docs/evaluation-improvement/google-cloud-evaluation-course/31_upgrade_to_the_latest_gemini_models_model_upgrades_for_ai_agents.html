In this lesson, you'll learn special concerns related to upgrading the foundation model behind an agent.

Unlike standalone prompts, AI agents make decisions, call tools, and execute multi-turn trajectories. A minor shift in reasoning behavior can derail planning loops or cause tool execution failures. To safely upgrade the foundation model powering an agent, you must bridge  two distinct cultures of testing—integrating traditional software engineering (SDLC) stateful environments with statistical machine learning (ML) evaluations. To do this, you'll explore how to construct sandbox testing harnesses with prod-like dependencies to validate complete agent trajectories.

By the end of this lesson, you'll be able to:

  1. 1.

    Explain why agentic architectures are sensitive to minor shifts in model behavior.

  2. 2.

    Differentiate between traditional software development lifecycle (SDLC) testing and machine learning (ML) evaluation for agentic systems.

  3. 3.

    Explain the infrastructure and dependency requirements for building agent testing harnesses.

The two cultures of software testing

To understand why agents are difficult to test, we must look at the two distinct cultures of software testing:

  • Traditional Software Development Life Cycle (SDLC) with its complex user criteria, prod-like dependencies, and a stateful environment.

  • ML evaluation with its statistical validity and bulk inference.

Agents represent the "worst of both worlds," requiring a cultural integration of both traditional software development practices and data science practices.
