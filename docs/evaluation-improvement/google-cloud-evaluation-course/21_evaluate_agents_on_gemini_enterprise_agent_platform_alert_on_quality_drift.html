The centralized gateway architecture

You wire an alert by picking an alerting-policy template, from either the Recommended Alerts modal or a per-monitor Create alerting policy flow, then attaching Notification Channels so it reaches Slack, email, or Pub/Sub. 

If you leave Use notification channels unchecked, the policy still records incidents you can review on the Monitoring > Alerting page, but it pages no one. Each incident carries the originating monitor's labels, so you can trace an alert back to the conversations that caused the drift and read them in the per-trace view.

Together, these pieces make production quality observable. A monitor scores live traffic, the dashboard and per-trace views show where quality moves, and an alerting policy pages you when a score drifts. What this module does not cover is what to do once an alert fires. That is Module 7, where you cluster the failures behind a drop, backtrack them to the turn that caused them, and close the loop with a verified fix.
