Both formats share one Pydantic data model. Once you understand its fields, you can edit a case precisely and change the exact part that controls the behavior you’re testing. An eval set holds eval_cases.

  • Each EvalCase (eval_id) holds a conversation of one or more Invocations (turns).

  • Each invocation pairs the user_content (the query) with the final_response (the reference answer) and an intermediate_data block whose tool_uses capture the expected tool trajectory.

The centralized gateway architecture

You rarely hand-write these files. The fastest way to author one is to capture a real session. Run adk web against your agents folder, interact with the agent until it does the right thing, then save that session as an eval case.

In the web UI, open the Eval tab, create or select an eval set, and click Add current session to turn the conversation you just had into an eval case. From there you can edit the saved case to tighten the reference answer or the expected tool trajectory.
