In this lesson, you'll learn about trajectories and how they are evaluated.

An agent's final output does not tell the whole story. If you only look at the end result, you might miss costly internal errors. You must analyze your agent's trajectories—its step-by-step internal logs. In this lesson, you'll review the ReAct loop that forms the basis of trajectories and walk through an example trajectory. Then, you'll learn the basics of trajectory evaluation.

By the end of this lesson, you'll be able to:

  1. Explain how the ReAct loop structures agent reasoning and execution.

  2. Trace the steps of an agent trajectory to identify logical flow and errors.

  3. Differentiate between final output correctness and trajectory correctness.

  4. Identify common trajectory evaluation techniques, including ground-truth matching and failure categorization.

To evaluate the internal behavior of an agent, you must understand how it reasons and acts. Most modern agent architectures rely on the ReAct (Reasoning and Acting) paradigm.

The ReAct loop is a cycle of three repeating stages:

Click the marker numbers in the diagram to learn more.

Thought
Action
Observation

In every execution turn, the agent follows this loop. It evaluates its progress, executes an action, and uses the observation to adjust its reasoning. This continues until the agent determines it has enough information to return a final answer.

While ReAct is a foundational concept, modern agent platforms often abstract these loop details from the developer and the loop is not always clean. For example, some foundation model serving stacks monitor thinking token generation, interrupt thinking to insert context, then return control to the model to continue generating thinking tokens. However, the core loop principles still apply: the agent must plan, act, and then repeat based on the latest observation.

A trajectory is the sequence of steps taken by a generative or agentic system to reach a solution. Essentially, it is a recorded log of each step as it is run.

Step-by-step trajectory analysis makes the agent steerable and debuggable. By reading the trajectory, you verify that each step logically follows the previous step. Mistakes in the logical progression of trajectory steps are how you debug malfunctions.

When you evaluate an agent, you must evaluate both the final trajectory outcome and the internal steps within the trajectory.

Evaluating the final trajectory outcome measures system output quality. However, if you only evaluate the final output, you cannot debug or hill climb your system. You may even end up launching a system that has many internal failures but a strong ability to recover. This might sound positive, but the system will be slower and more expensive. The system also becomes highly sensitive to small changes. For example, minor updates to tools or the foundation model can break recovery behaviors, causing sudden drops in output quality.

Evaluating internal trajectory steps is most useful when hill climbing. Trajectories allow you to isolate and catalog failure patterns like reasoning errors, tool misuse, or loop stagnation. You can then use these patterns to set hill climbing priorities.
