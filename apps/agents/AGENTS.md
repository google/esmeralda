# apps/agents/AGENTS.md

Local rules for agent packages. The root `AGENTS.md` still applies. Library details:
`docs/src/4-esmeralda-library/guide.md`.

## Package shape

Each agent is a uv workspace member (listed in the root `pyproject.toml`) with:

- `agent.yaml`: `framework` (`google-adk` or `a2a`), `env` (deployed values), `local_env` (workstation overrides applied by `--local`), `resources`, and for A2A the `agent_card`. Terraform reads it at deploy time (`agent_config_path`).
- `agent/__init__.py`: calls `esmeralda.prepare()` **before** importing the agent definition, then exports `app = esmeralda.create_app(root_agent, plugins=[...])`.
- `agent/agent.py` (+ helpers), `tests/`, `pyproject.toml` (depends on `esmeralda` with `[tool.uv.sources] esmeralda = { workspace = true }`), `Dockerfile`.
- The `Dockerfile` installs `requirements.lock` with `--require-hashes` and the `esmeralda` wheel from `dist/` (both generated by `make build-<agent>`), uses `ENTRYPOINT ["esmeralda", "run", "--"]` and `CMD ["esmeralda", "serve", "--otel-to-cloud"]`. Never bake certificates or env-specific values into the image.

## ADK vs A2A

| | ADK (`cx-mortgage-orchestrator`) | A2A (`ai-coe-mortgage-specialist`) |
|---|---|---|
| `framework` | `google-adk` | `a2a` |
| Served as | `adk api_server` (Agent Runtime `streamQuery`) | A2A REST server, card from `agent_card` at `/v1/card` |
| Terraform module | `infrastructure/modules/5-workloads/agents/adk-agent` | `infrastructure/modules/5-workloads/agents/a2a-agent` (+ Agent Registry entry, Cloud SQL task store) |
| Called by | End users / clients | Other agents, through the entry point |

Orchestrators belong to the CX team (`cx-*`); reusable A2A agents to the AI CoE team (`ai-coe-*`).

## Reaching MCP servers and other agents

Always through the entry point hostnames, with the `esmeralda` helpers, which add the ID token,
the user's token and the `X-API-Key`:

```python
from esmeralda import a2a, mcp

dms = mcp.toolset(os.environ.get("DMS_MCP_URL", "https://legacy-dms.esmeralda.internal/mcp"), prefix="dms")
specialist = a2a.remote_agent("mortgage_tools_agent", url=os.environ["A2A_AGENT_URL"], description="...")
```

- URLs come from `agent.yaml` `env` (`https://<name>.esmeralda.internal[/mcp]`) and `local_env` (`http://localhost:800x/mcp`). Never hardcode `run.app` or Reasoning Engine URLs, and never mint tokens by hand.
- A new destination needs an Agent Registry entry and an `iap.egressor` grant (`infrastructure/AGENTS.md`), plus a route in the gateway.

## Run and test

- `make test-agents`: agent + library unit tests.
- `make query AGENT=<dir>`: in-process query with the local MCP servers started for you. `make serve AGENT=<dir> [WEB=1]`: local server as in the container.
- After deploying: `make query AGENT=cx-mortgage-orchestrator TARGET=remote ENV=<env>` must return an answer.
- A new agent also needs: a workspace member entry, `build-<agent>` / `deploy-<agent>` Make targets, a unit under `infrastructure/live/<env>/layer-5-workloads/agents/`, and an entry in `env.yaml` `catalog` (+ dependency in `gateways/direct`).
